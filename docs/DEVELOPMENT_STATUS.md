## 1. 현재 결론 — 먼저 읽기

**SsCalendar의 자체 일정 기능과 외부 일정 조회·위젯 표시는 유지한다. 외부 일정의 상세 화면 진입 및 수정·삭제, 외부 캘린더로 새 일정 저장은 현재 사용자에게 제공하지 않는다.**

- 외부 일정은 **앱의 월간/일간 일정과 위젯에서 볼 수 있다**.
- 외부 일정을 눌러도 **Apple 일정 세부사항 화면에 들어갈 수 없다**.
- 외부 일정의 **수정·삭제 및 D-Day 설정 경로는 차단**한다.
- 새 일정은 **SsCalendar 자체 저장소에 저장**한다. 외부 캘린더 저장 위치 선택 UI는 숨겨져 있다.
- **SsCalendar 자체 일정의 작성·수정·삭제·반복·D-Day 및 해당 위젯은 그대로 유지**한다.
- 기존 외부 일정의 상세·편집·삭제 및 외부 저장 구현 코드는 **삭제하지 않고 보존**했다. 따라서 **기능 포기나 원인 해결이 아니라, 임시 비활성화**에 해당한다.
- 외부 일정 편집 관련 결함 **두 건의 원인은 아직 확정되지 않았다**. 다른 캘린더 앱의 상호 편집 지원 사례도 아직 검증하지 않았다.

## 4. 현재 사용자에게 제공하는 기능

### 4-1. SsCalendar 자체 일정

- 자체 일정의 **생성·조회·수정·삭제**.
- 일정 제목·메모, 시작·종료 및 하루 종일 설정, 색상, 알림 등의 편집 기능.
- 반복 일정 및 개별 발생분 처리(개별 수정/삭제 예외) 기능.
- 월간·일간 화면, 연간 달력 및 화면 이동.
- 자체 일정의 **D-Day ON/OFF, 편집 시 D-Day 미리보기**, 관련 홈 화면/잠금화면 위젯.
- 중형 D-Day 홈 위젯은 가까운 일정 최대 2건을 40:60 두 열과 중앙 구분선으로 표시하며, 각 행을 터치하면 **그 일정이 속한 날짜의 일간 화면**으로 이동. 편집 화면을 자동으로 열지 않음. 소형 위젯의 기존 동작은 유지.
- 위젯의 Today/Next 일정 표시.
- 한국어/영어, 한국/미국 공휴일 관련 기능.

**D-Day 현재 정책:** SsCalendar **자체 일정**을 대상으로 한다. 외부 일정에는 D-Day 설정을 제공하지 않는다. 지난 D-Day의 위젯 노출 및 반복 일정의 다음 발생일 계산은 기존 구현 규칙을 보존하는 것이 원칙이며, 최신 변경에서 계산 코드를 다시 설계하지 않았다.

### 4-2. 외부 캘린더 — 현재는 읽기 전용

| 동작 | 현재 처리 |
|---|---|
| 외부 일정 불러오기 | 유지 |
| 월간/일간 화면 표시 | 유지 |
| 위젯의 외부 일정 표시 | 유지 |
| 외부 일정 탭 → 상세 화면 | **차단** |
| 외부 일정 수정·삭제 | **차단** |
| 외부 일정 D-Day 설정 컨텍스트 메뉴 | **차단** |
| 신규 일정의 외부 캘린더 저장 위치 선택 | **숨김** |
| 기존 외부 계정/권한 및 연동 설정 | 유지 |
| 외부 저장/편집/삭제 관련 기존 코드 | 보존(현재 접근 경로 비활성) |

현재 UI의 차단은 외부 캘린더 데이터 삭제가 아니다. **외부 일정 자체는 원래 캘린더 및 계정에 그대로 존재**한다.

## 5. 현재 미해결 문제 — 사실과 가설을 구분

### 이슈 A. 외부 일정 편집 화면에서 한글 조합 깨짐

**실제 확인된 현상**

- SsCalendar에서 외부 일정을 열어 Apple 편집 화면에서 한글 입력 시 자모 조합이 깨짐.
- 예: `광장`을 입력할 때 `ㄱㅘㅇ 장`, `고기`를 입력할 때 `ㄱㅗ기` 등.
- 실제 기기 비교 테스트:
  - SsCalendar **자체 일정** 편집: 당시 정상.
  - SsCalendar 외부 연동 ON/OFF 상태의 자체 일정 편집: 당시 정상.
  - **동일 외부 일정**을 iPhone 기본 캘린더 앱에서 편집: 정상.
  - SsCalendar 안에서 **외부 일정 편집**: 즉시 재현.
- 자체 일정 제목에서도 **과거 간헐적인 한글 조합 이상 보고가 있었다**. 최근 단기 테스트가 정상이라고 완전 해결을 확정해서는 안 됨.

**코드 조사에서 확인된 사실**

- 현재 원래의 외부 편집 진입 구조는 `DayScheduleView` → SwiftUI `.sheet(item:)` → `SystemEventDetailView` → `EKEventViewController` → Apple 내부 편집 화면.
- 현재 소스가 외부 편집 화면의 텍스트 필드나 `markedTextRange`를 직접 조작한다는 근거는 Codex 조사에서 발견되지 않음.
- `UIViewControllerRepresentable.updateUIViewController()`는 완료 콜백 갱신 위주로, 내부 편집 텍스트 필드를 직접 다시 만든다는 증거 없음.
- 외부 일정용 입력은 앱의 `CompositionSafeTextField`/`CompositionSafeTextEditor`와 별개의 Apple EventKitUI 입력 화면.

**원인 후보 — 아직 검증되지 않음**

1. `EventKitUI` 편집 화면이 현재 앱의 SwiftUI/UIKit 표시 환경과 결합될 때 발생하는 IME 문제.
2. SwiftUI 시트, UIKit 내비게이션, 화면 갱신/생명주기 상호작용.
3. EventKit 변경 알림 또는 이벤트 객체/저장소 관리의 간접 영향(코드상 직접 증거 부족).

**중요:** 위 내용은 *원인 확정이나 Apple 버그 입증이 아님*. iPhone 기본 캘린더 앱이 정상이어도 `EKEventEditViewController`와 동일한 내부 구현을 사용한다고 단정할 수 없다.

### 이슈 B. 외부 일정 상세 화면의 삭제 버튼이 순간적으로 중복 표시됨

**실제 확인된 현상**

- 외부 일정 상세 화면의 삭제 버튼/툴바가 순간적으로 이중 표시되거나 작은 반투명 버튼처럼 깜빡이는 현상.
- 기존 방식에서 **외부 일정 삭제 기능 자체는 작동**했지만 UI 완성도 문제로 판단.
- 과거에 `d7cbb44`라는 삭제 버튼 관련 수정 커밋이 있었지만, 최종적으로 이 현상이 완전히 제거됐다는 검증은 없음.

**기존 화면 구성**

- `EKEventViewController`를 `SystemEventNavigationController`로 감싸 표시.
- Apple 컨트롤러의 툴바 동작과 앱의 툴바 숨김 처리가 맞물리는 지점이 의심됐지만 **정확한 원인은 미확정**.

**현재 대응**

- 외부 상세 화면 진입 자체가 차단되어 사용자에게 현재 문제 화면이 노출되지 않음.
- 근본 해결은 아니며, 향후 기능 재개 전 재검증 필요.

## 6. 실제 시도했으나 해결하지 못한 개선 작업

### 6-1. 외부 상세 화면을 생략하고 Apple 편집 화면을 바로 표시

**의도:** 상세 화면을 없애면 삭제 버튼 중복 표시 문제를 피할 수 있다고 판단.

**관찰된 결과:**

- 중복 삭제 버튼 표시 문제는 해당 경로에서 회피됨.
- 그러나 **외부 일정을 삭제하면 EventKit 데이터는 삭제되는데 편집 화면이 닫히지 않고 멈춤**. X 버튼 등 종료 동작도 먹지 않는 현상 재현.
- 저장 및 취소 경로에서는 정상 완료되는 경우가 있었으나 삭제 경로에서 문제가 발생.

**시도한 방식(모두 채택하지 않음)**

- SwiftUI `.sheet` + `EKEventEditViewController` + delegate dismiss/state 해제.
- `.equatable()` 등을 통한 불필요한 View 업데이트 억제 시도.
- 별도 UIKit 호스트(`SystemEventEditPresenter`)에서 `present()`로 표시.
- 편집 중 `changeToken` 등 변경 갱신을 동결하는 방식.

**디버깅 기록**

- `[EDITTRACE]` 등 로그/중단점으로 삭제·저장·취소 경로 조사.
- 삭제 시 `EKEventStoreChanged`, `updateUIViewController` 갱신은 관찰했으나 `eventEditViewController(_:didCompleteWith:)` 완료 콜백은 호출되지 않는 현상이 관찰됨.
- **갱신이 삭제 후 정지의 원인이라고 입증된 것은 아님**. 저장/취소에서도 갱신이 발생했기 때문.

**최종 처리:** 직접 편집 화면 진입 실험은 취소하고, `635301f`의 **기존 상세 → 편집 구조로 복구**. 같은 추측성 실험을 반복하지 않기로 결정.

### 6-2. 한글 조합 깨짐을 막기 위한 입력 동기화 수정

**기존 기준 코드:** `EventEditorView.swift`의 UIKit 기반 `CompositionSafeTextField` 및 `CompositionSafeTextEditor`.

- 입력 중 `markedTextRange`가 존재하면 SwiftUI Binding 반영을 보류하는 로직 존재.
- `updateUIView`에서 UIKit의 `text`와 SwiftUI Binding의 불일치를 다시 주입할 수 있는 로직 존재.

- Google Calendar에서 생성·삭제한 일정은 iPhone 기본 캘린더와 SsCalendar에 반영되지만 지연이 관찰됨.
- iPhone 기본 캘린더에서 생성한 Google 일정은 상대적으로 빠르게 반영됨.
- 사용자의 테스트에서는 Google 일정의 수정에도 제약이 관찰됐음. 정확한 원인과 캘린더 권한에 따른 차이는 검증되지 않았으므로 Google 전체의 기능 제한으로 단정하지 않음.
- 카카오톡 캘린더는 앱 설치만으로 iPhone 시스템 캘린더에 나타나지 않았음.

**2. SsCalendar의 기존 구현 경험**

- SsCalendar는 과거 EventKit을 통해 외부 일정 조회·수정·삭제 기능을 구현한 경험이 있음.
- 실제 일정 수정·삭제가 작동했으나, 한글 입력 깨짐과 삭제 버튼 중복 표시 문제가 있었음.
- 현재는 안정성을 위해 외부 일정 편집 기능을 비활성화하고 코드는 보존 중임.

**3. 제품 경쟁력 관점**

타사 제품과의 실제 사용 비교에서 확인된 불편함은 SsCalendar의 개선 기회가 될 수 있음.

특히 다음 기능을 안정적으로 제공한다면 제품 경쟁력 향상에 도움이 될 가능성이 있음.

- 넓은 월간 달력에서 여러 캘린더의 일정 통합 조회
- 외부 캘린더 일정의 안정적인 수정·삭제
- 외부 일정 변경사항의 신속한 화면 반영
- 사용자에게 복잡한 연동 과정을 최소화하는 설정 경험

단, 외부 일정 수정 자체는 타사에서도 지원할 수 있으므로 독점 기능으로 표현하지 않음.

**4. 향후 검토 사항**

- 기존 외부 일정 편집 기능의 오류 해결 및 재활성화
- Google Calendar 직접 API 연동의 필요성과 개발 비용 검토
- Google ↔ iPhone 동기화 지연과 SsCalendar 자체 갱신 지연의 구분

현재는 기술적·사업적 검토 후보로 기록하며 개발은 진행하지 않음.

### 유지하는 보류 사항

- 외부 캘린더 일정의 추가·수정·삭제가 위젯에 즉시 반영되지 않는 문제는 **보류 유지**. 외부 일정에 D-Day를 설정하는 경로는 현재 차단되어 있음.
- 외부 일정 편집 화면의 한글 조합 문제와 삭제 버튼 중복 표시는 **미해결**. 읽기 전용 정책 유지.
- 자정 경계에서 위젯 갱신 시점은 WidgetKit 시스템 동작의 영향을 받을 수 있으며, 자정 직후 즉시 갱신을 보장한다고 기술하지 않음.
